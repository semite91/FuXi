B. APPLYING THE CHOSEN TEMPLATE
==================================================
B1. [RV] Given the chosen option, when it is applied, then its colors are only in color.less, with the light and dark modes.
B2. [RV] Given the chosen option, when it is applied, then its fonts and font sizes are only in typography.less, with the big-font and small-font modes kept.

B4. [RV] Given a chosen web font, when it is added, then it is vetted before install, its files are in wwwroot, and the built app loads no font from another site.
B5. [FE] Given a build, when it ends, then the service worker holds the list of the built font files and a cache name made for that build; on install it caches every listed font, on activate it deletes the older font caches, and a font request is answered from the cache, also offline after the first visit, and a font missed by the cache is fetched and stored; fonts from another site, other files and non-GET requests are left to the browser.
B6. [RV] Given the components' .less files, when they are read, then no new color, font, border or spacing value is hardcoded; they use the tokens.
B7. [RV] Given every page (Words, Flashcard, Active Words, Schedule, Configs, Settings), when it is opened in a browser (light mode), then it shows the chosen template, the logo is unchanged, and nothing overlaps or overflows at phone width.
B8. [RV] Given the light mode, when the page background is read, then it is still #FCFAEE.
B9. [FE] Given the frontend tests, when "npm test" runs, then the existing tests still pass.
B10. [FE] Given a browser with Static Routing (InstallEvent.addRoutes), when the worker installs, then only the app's font requests are routed to the worker and other requests go to the network; without it the worker still works.
B11. [RV] Given the bundled fonts, when they are listed, then only the Baloo 2 weight used by the display font (800) is imported.
B12. [FE] Given the build step that fills the worker's font list, when a build failed, when the build runs again in watch mode, or when the output folder is an absolute path, then it skips the failed build, fills the list again and finds the worker; the placeholders are defined in one shared module, and the cache name and the list are written literally, also when they hold a $.
B13. [FE] Given a font precache slower than its time limit, when the worker installs, then the install ends at the limit, the worker becomes active and push keeps working; fonts not stored yet are stored by the fetch rule.
B14. [FE] Given the dev server's worker (no font list), when a font is asked, then nothing is cached and the request is left to the browser.
