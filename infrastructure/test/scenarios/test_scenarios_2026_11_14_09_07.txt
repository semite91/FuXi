Every scenario has one purpose. "Given / When / Then" is used.
Phase 5c adds the third source to the RAG engine: the Learner's watched movies. Letterboxd gives the list, TMDB gives
each movie's details. One text document per movie is embedded with Qwen into fuxi_text.
Spotify (5d) comes later. Evaluation (ragas) is version 2.

Decisions taken by the Learner on 2026-11-14 (grilling rounds 1 and 2):
- Q1 The watched list is Letterboxd's own data export: the Learner saves watched.csv in the git-ignored folder
  rag/data/letterboxd/. No Letterboxd API (closed beta), no RSS feed, no scraping. project.md is updated to say so.
- Q2 TMDB is called with its API Read Access Token, RAG_TMDB_TOKEN in the root .env, sent as "Authorization: Bearer".
- Q3 The Settings page gets a Credits block with the TMDB notice and the approved TMDB logo (TMDB terms).
- Q4 A row is matched by searching TMDB with its name and year; the first result whose release year equals the row's
  year is taken. No such result: the movie is skipped and counted in the read summary.
- Q5 The top 10 billed actors go into the document.
- Q6 A missing watched.csv or an empty RAG_TMDB_TOKEN makes the source fail; the build is not complete and the old
  collections are kept.
- Q7 TMDB is asked in English (language=en-US).

Proposed by Claude, to confirm with these scenarios:
- RAG_LETTERBOXD_WATCHED_FILE in the root .env holds the path of watched.csv (default text in the examples:
  rag/data/letterboxd/watched.csv); a relative path is resolved from the repository root, like the 5b key path.
- watched.csv is read with Python's csv module as UTF-8 (a BOM is allowed). The columns Name and Year are required,
  Date is used for the timestamp. A row with an empty name or a year that is not a number is skipped and counted.
  The same name and year twice is read once.
- For each row: GET /3/search/movie?query=<Name>&year=<Year>&language=en-US, then
  GET /3/movie/<id>?append_to_response=credits&language=en-US. No new library: the installed httpx and the shared
  rag/resources/http_retry.py helper (429, 5xx, dropped connection and timeout wait 1, 2, 4, 8 seconds, at most 5
  attempts; Retry-After is followed). A 401 fails the source. A 404 on the details call skips the movie.
- The movies are looked up in parallel by a few workers (4, like Drive); documents keep the order of watched.csv.
- Document text, one movie per document, no splitter:
    <Title> (<Year>)
    Director: <names>
    Music: <names>
    Screenplay: <names>
    Genres: <names>
    Actors: <top 10 names>
    Summary: <overview>
  A line without a value is left out. Names are joined with ", ".
  Director = crew job "Director"; Music = crew job "Original Music Composer"; Screenplay = crew department "Writing"
  with job "Screenplay" or "Writer"; Actors = cast in TMDB's order.
- Metadata: name (TMDB title), director, musician, genre (each joined with ", ", empty text when none), timestamp
  (the watched Date of watched.csv, ISO date) and type "text".
- Gemini receives the movie documents as text context like Notion pages; the prompt files are not changed.
- The Credits block is shown at the bottom of the Settings page: the TMDB logo (an approved logo file kept in the
  frontend, not loaded from the web) and the sentence "This product uses the TMDB API but is not endorsed or
  certified by TMDB."
- Live tests call the real TMDB only when RAG_LIVE_TESTS=true in .env.test, and only after the Learner's go-ahead.

Marks:

[LIVE] Python scenario, verified by a pytest test that calls the real TMDB or loads the real models; runs only when enabled.
[FE]  frontend scenario, verified by a Vitest test.

==================================================
C. LETTERBOXD WATCHED LIST
==================================================
C1. [PY] Given a recorded watched.csv, when it is read, then each row gives its name, year and watched date.
C2. [PY] Given a watched.csv that starts with a UTF-8 BOM and has non-English names, when it is read, then the first column and the names are read correctly.
C3. [PY] Given a watched.csv path that does not exist, when the resource reads, then it fails and the error names RAG_LETTERBOXD_WATCHED_FILE without the full path.
C4. [PY] Given a watched.csv without the Name or the Year column, when the resource reads, then it fails and the error names the missing column.
C5. [PY] Given a row with an empty name or a year that is not a number, when it is read, then it is skipped, the other rows are read and the skip is counted.
C6. [PY] Given the same name and year in two rows, when they are read, then TMDB is asked once and one document is made.
C7. [PY] Given a watched.csv with only the header row, when the resource reads, then it gives no document and no error.
C9. [PY] Given two rows with different names that match the same TMDB movie, when the resource reads, then one document is made and the second row is counted as repeated.
C8. [PY] Given a watched.csv that cannot be opened or read (for example locked by another program), when the resource reads, then it fails and the error names RAG_LETTERBOXD_WATCHED_FILE without the file's path.

==================================================
D. TMDB LOOKUP
==================================================
D1. [PY] Given an empty RAG_TMDB_TOKEN, when the resource reads, then it fails before any call and the error names RAG_TMDB_TOKEN.
D2. [PY] Given a TMDB call, when it is sent, then it carries "Authorization: Bearer <token>" and the token is not in the URL.
D3. [PY] Given a row, when it is searched, then /3/search/movie is called with query=<Name>, primary_release_year=<Year> and language=en-US.
D4. [PY] Given search results where the first has another year and the second has the row's year, when the match is chosen, then the second is taken. Among the results of the row's year, one whose title or original title equals the row's name is taken first (both are compared in lowercase, with the Turkish letters turned into their Latin equivalents: ı and İ to i, ö to o, ü to u, ş to s, ğ to g, ç to c); without one, the first result of that year is taken.
D5. [PY] Given search results with no result of the row's year, or no result at all, when the match is chosen, then the movie is skipped and counted.
D6. [PY] Given a result without a release date, when the match is chosen, then it does not count as the row's year.
D7. [PY] Given a match, when its details are asked, then /3/movie/<id> is called once with append_to_response=credits and language=en-US.
D8. [PY] Given a 404 on the details call, or a 400 or 422 on a movie's search or details call, when the resource reads, then the movie is skipped and counted, and the others are still read.
D9. [PY] Given a 401 answer, when the resource reads, then the movie resource fails.
D10. [PY] Given a 429 answer with Retry-After, when the resource reads, then it waits as Retry-After says and tries again.
D11. [PY] Given a 5xx answer, a dropped connection or a timeout, when the resource reads, then it waits 1, 2, 4 and 8 seconds and tries again, at most 5 attempts, then fails the source.
D12. [PY] Given 10 rows, when they are looked up in parallel by a bounded number of workers, then the documents keep the order of watched.csv.
D13. [PY] Given a movie read, when it ends or fails, then its summary holds the rows, movies, skipped rows (bad row, no match, not found, refused with 400 or 422), repeated rows, calls, rate limit waits, network retries and seconds.
D14. [PY] Given the new resource class, when it is added, then it implements the Resource base with kind TEXT, uses rag/resources/http_retry.py, and the Notion and Drive resources do not change.
D16. [PY] Given a TMDB answer that fails the source (401, or 5xx after every attempt) or any other httpx error (for example an answer that cannot be decoded), when the error is raised, then it holds the status and the endpoint, not the movie's name and not the token.
D17. [PY] Given a read that fails after some movies were read or skipped, when its summary is written, then it counts the movies and skips finished so far.
D18. [PY] Given a 200 answer whose body is not a JSON object, when the resource reads, then the movie resource fails with a TMDB error that holds the endpoint, not the movie's name.
D19. [PY] Given rows that are all refused by TMDB with 400 or 422, when the resource reads, then the movie resource fails; when at least one row is not refused, the refused rows are skipped as in D8.
D20. [PY] Given a network error that cannot pass by trying again (for example a malformed request header or an unsupported protocol), when a Notion, Drive or TMDB call fails with it, then it is not tried again; a timeout, a failed connection, a read or write error and a dropped connection are still tried again.
D15. [LIVE] Given the real TMDB token and 3 known movies, when the resource reads, then 3 documents with a director and actors are returned.

E. MOVIE DOCUMENT
==================================================
E1. [PY] Given recorded details with credits, when the document is built, then its text has the title and year, Director, Music, Screenplay, Genres, Actors and Summary lines.
E2. [PY] Given crew with several jobs, when the document is built, then Director is job "Director", Music is job "Original Music Composer", and Screenplay is department "Writing" with job "Screenplay" or "Writer".
E3. [PY] Given a cast of 15 actors, when the document is built, then the first 10 in TMDB's order are listed.
E4. [PY] Given a person listed twice in the same role (for example two writing jobs), when the document is built, then the name appears once in that line.
E5. [PY] Given a movie without a composer or without an overview, when the document is built, then that line is left out and the document is still made.
E6. [PY] Given a movie, when its metadata is built, then it has name, path (empty text), director, musician, genre (joined with ", "), timestamp (the watched date) and type "text", and every value is a string.
