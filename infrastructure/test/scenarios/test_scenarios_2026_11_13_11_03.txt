FuXi - Phase 5a - RAG engine core and Notion
Test scenarios, shredded to atomic processes.
Created: 2026-11-13 11:03 UTC
Status: CONFIRMED BY THE LEARNER ON 2026-11-13, with the proposals by Claude
Amended on 2026-11-13 for the code review fixes approved by the Learner: A8, I1, I7, I11 and the requirements changed;
B6, C11, E10, E11, G18, H12 to H15 and I15 to I19 were added. Review item 6 (image embedding input) moves to Phase 5b.

Every scenario has one purpose. "Given / When / Then" is used.
Phase 5a builds the Python RAG engine in /rag (FastAPI, ChromaDB, Qwen3-Embedding-0.6B, CLIP, Gemini) with one real
source, Notion, and the frontend changes it needs. Google Drive (5b), Letterboxd + TMDB (5c) and Spotify (5d) come later.
Evaluation (ragas) is version 2.

Decisions taken by the Learner on 2026-11-13 (grilling rounds 1 and 2):
- Phase 5 is split: 5a is the engine core plus Notion; each later source has its own scenarios, PR and confirmation.
- The engine runs natively on Windows with Python 3.13 and CPU-only PyTorch (the GTX 660 is not supported by CUDA 12).
- Word Content is structured JSON stored as a string in Words.Content (no migration). The card renders text, picture and
  music layouts, built from the existing card style. An old plain-text Content is shown as a story.
- The code picks one of the 5 methods at random (story, quote, film reference, photo, music) and sends it to Gemini as
  "available_methods": ["<chosen>"]. photo and music use prompts/llm_web.txt with the google_search tool; the others use
  prompts/llm.txt. The prompt files are not changed. On insufficient_context one other random method is tried once.
- prompts/retrieval.txt is sent to Gemini with the word and its meaning; Gemini writes the search query; the query is
  embedded with Qwen (text collection) and CLIP (image collection).
- The frontend sends each Word with its Translation as the meaning: POST /GetWordContent { "words": [{ "name", "translation" }] }.
- The frontend calls Init_RAG on every app open. It is cheap when collections have data and starts one background build when
  they are empty. While a build runs, GetWordContent answers "not ready".
- In 5a, photo means a web image found by Google Search. When Drive comes (5b), Gemini may choose the Learner's own image.
- Similarity threshold is one setting per collection: text 0.5 and image 0.25 to start, tuned on real data.
- Gemini uses gemini-3.8-flash on the free tier; when grounding is refused the fallback rule applies.
- Notion: every page shared with the integration. Notes longer than 2000 characters are split with a 200-character overlap.
- Secrets and settings are RAG_ keys in the root .env. ChromaDB data is in rag/chroma_data/, logs in logs/embedding/
  named yyyy_MM_dd_HH_mm.txt; both are git-ignored. Embedding batch size is 16.
- ChromaDB 1.5.9 is used embedded only (PersistentClient), with precomputed embeddings and anonymized_telemetry off,
  because its 4 open CVEs are in its HTTP server.

Proposed by Claude, to confirm with these scenarios:
- Content JSON shapes. Text methods: {"method","title","content","source_reference"}. photo: {"method","image_url"}.
  music: {"method","song_title","artist","song_url","lyrics_excerpt"}. "method" is the method name Gemini returned.
- GetWordContent answers [{ "name", "content" }] where content is that JSON string; a Word without content is left out.
- GetWordContent and Update_Collections answer 503 while a build runs. Update_Collections waits until the rebuild ends
  and then answers 200, so the Settings dialog shows the real result.
- Init_RAG is POST /Init_RAG and answers {"status": "ready"} (200) or {"status": "building"} (202).
- Collections are named fuxi_text and fuxi_image, both with cosine distance.
- The engine is started with: uvicorn engine:app --port 8000 (from /rag).
- Live tests (real models, real Notion and Gemini) run only when RAG_LIVE_TESTS=true in .env.test.

Marks:
[PY]  Python scenario, verified by a pytest test with a fake embedder and recorded Notion and Gemini answers.
[LIVE] Python scenario, verified by a pytest test that loads the real models or calls a real API; runs only when enabled.
[FE]  frontend scenario, verified by a Vitest test.
[RV]  verified by reading the code, running a command or a real run.

==================================================
C. NOTION RESOURCE
==================================================
C1. [PY] Given recorded Notion search answers over 2 result pages, when the resource reads, then every shared page is read once.
C2. [PY] Given a page with nested blocks, when it is read, then the text of the nested blocks is included in order.
C3. [PY] Given block children over 2 result pages, when a page is read, then every block is read.
C4. [PY] Given a page, when its document is built, then metadata has name (page title), path (parent titles joined with " / "), type "text" and timestamp (last edit time).
C5. [PY] Given a page whose text is at most 2000 characters, when it is chunked, then it gives one document.
C6. [PY] Given a page whose text is longer than 2000 characters, when it is chunked, then it is split by RecursiveCharacterTextSplitter into parts of at most 2000 characters with 200 characters overlap.
C7. [PY] Given a page without text, when it is read, then it gives no document.
C8. [PY] Given a Notion answer 429 with Retry-After, when the resource reads, then it waits and tries again.
C9. [PY] Given a new resource class, when it is added, then it implements the Resource base and no existing class is changed (open-closed).
C11. [PY] Given a shared page whose parent is not shared, when it is read, then the page is embedded and its path stops at the first unreadable parent.
C10. [LIVE] Given the real Notion token, when the resource reads, then at least one document is returned.

F. RAG CLIENT
==================================================
F1. [PY] Given init, when it runs twice, then the collections are opened once and the same object is returned (singleton).
F2. [PY] Given a query, when retrieve runs, then the query is embedded with Qwen for fuxi_text and with CLIP for fuxi_image.
F3. [PY] Given each collection, when it is queried, then n_results is 20.
F4. [PY] Given results with similarities 0.7, 0.5 and 0.3, when the text threshold is 0.5, then 0.7 and 0.5 are kept.
F5. [PY] Given image results, when the image threshold is 0.25, then results below it are dropped.
F6. [PY] Given retrieve, when it returns, then it gives two lists: text results and image results, each with document, metadata and similarity.
F7. [PY] Given empty collections, when retrieve runs, then both lists are empty and no error is raised.
F8. [PY] Given an update, when Update_Collections ends, then the singleton points to the new collections.

==================================================
G. LLM CLIENT
==================================================
G1. [PY] Given a word and its meaning, when the search query is asked, then prompts/retrieval.txt is sent with {"word","meaning"} as input.
G2. [PY] Given Gemini's retrieval answer {"query": "..."}, when it is read, then that query is used for retrieve.
G3. [PY] Given an invalid retrieval answer, when it is read, then "<word>: <meaning>" is used as the query.
G4. [PY] Given a fixed random source, when the method is chosen, then it is one of story, quote, film reference, photo and music.
G5. [PY] Given the chosen method story, quote or film reference, when Gemini is called, then prompts/llm.txt is used without tools.
G6. [PY] Given the chosen method photo or music, when Gemini is called, then prompts/llm_web.txt is used with the google_search tool.
G7. [PY] Given a call, when its input is built, then it holds word, meaning, available_methods ["<chosen>"] and the retrieved text and image results.
G8. [PY] Given a call, when it is made, then the model is RAG_GEMINI_MODEL.
G9. [PY] Given a success answer for a text method, when it is read, then the content JSON is {"method","title","content","source_reference"}.
G10. [PY] Given a success answer for photo, when it is read, then the content JSON is {"method","image_url"}.
G11. [PY] Given a success answer for music, when it is read, then the content JSON is {"method","song_title","artist","song_url","lyrics_excerpt"}.
G12. [PY] Given an image_url or song_url that is not an https URL, when it is read, then the answer counts as insufficient_context.
G13. [PY] Given an answer with status insufficient_context, invalid JSON or empty text, when it is read, then one other random method is tried once.
G14. [PY] Given the second method also fails, when it is read, then the word gets no content.
G15. [PY] Given Gemini refuses the google_search tool, when it answers with an error, then it counts as a failed method and the fallback rule applies.
G16. [PY] Given a Gemini error for one word, when generate runs for 3 words, then the other words still get content.
G18. [PY] Given several calls, when prompts are used, then each prompt file is read once.
G17. [LIVE] Given the real Gemini key, when one word is generated, then the answer is a valid content JSON or no content, without an error.

H. ENGINE API
==================================================
H1. [PY] Given the engine, when its routes are listed, then POST /GetWordContent, POST /Init_RAG and POST /Update_Collections exist.
H2. [PY] Given ready collections, when POST /GetWordContent is called with 2 words, then 200 and [{ "name", "content" }] are returned for words with content.
H3. [PY] Given a body without words, with an empty name, or with more than 50 words, when it is called, then the answer is 422.
H4. [PY] Given empty collections, when POST /Init_RAG is called, then 202 {"status":"building"} is returned and one background build starts.
H5. [PY] Given a running build, when POST /Init_RAG is called again, then 202 is returned and no second build starts.
H6. [PY] Given collections with data, when POST /Init_RAG is called, then 200 {"status":"ready"} is returned and nothing is built.
H7. [PY] Given a running build, when POST /GetWordContent is called, then the answer is 503.
H8. [PY] Given ready collections, when POST /Update_Collections is called, then it rebuilds and answers 200 when the rebuild ends.
H9. [PY] Given a running build, when POST /Update_Collections is called, then the answer is 503.
H10. [PY] Given a request from an origin in FUXI_CORS_ORIGINS, when it is sent, then the CORS headers allow it; another origin is not allowed.
H11. [PY] Given an error inside the engine, when it answers, then the body has no stack trace and no secret.
H12. [PY] Given a GetWordContent request in flight, when Update_Collections starts, then the update waits for it to finish, and new GetWordContent requests answer 503.
H13. [PY] Given a build that stopped partway, when Init_RAG is called, then a new build starts.
H14. [PY] Given a build that found 0 documents, when Init_RAG is called again in the same engine run, then no new build starts.
H15. [PY] Given a name with a trailing space, when content is generated, then the answer uses the same name with the space.
